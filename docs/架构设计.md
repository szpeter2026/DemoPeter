# szpeter2026 架构设计

## 设计理念

吸收自 Wukong 工作区三大项目的精华：

1. **Wukong** — 多源元数据管理、schema 映射、工具链设计
2. **72changes** — RAG 知识库、Chroma + AI 问答
3. **data/** — 多数据库统一运维、Web 看板

## 核心设计决策

### 1. 为什么选择 Python + Flask + SQLite？

- **轻量零配置**：无需 Java/Maven/Docker 等重型依赖
- **快速启动**：单文件 SQLite 元数据库，无需安装数据库服务
- **统一技术栈**：Python 贯穿文档处理、向量检索、AI 调用、Web 面板
- **易于扩展**：Flask 插件生态丰富，可方便扩展 API

### 2. 为什么选择 Chroma + pgvector 双向量后端？

- **Chroma**：轻量级，PersistentClient 零依赖本地运行 / HttpClient 连接 Docker 服务
- **pgvector**：基于 PostgreSQL，支持向量+关系数据混合查询，生产级稳定性
- 自动降级：Chroma 不可用时自动切换到 pgvector，两者都不可用则纯 AI 模式

### 3. Embedding 服务

- **Ollama nomic-embed-text**：768 维本地嵌入模型，通过 Docker Ollama 容器提供
- 与 LLM（qwen2.5:7b）共用同一 Ollama 服务，资源高效

### 4. AI 双模式设计

```
AIClient
├── DeepSeek 模式（默认）
│   └── 云 API，质量高，需联网和 API Key
└── Ollama 模式（备选）
    └── 本地运行，隐私好，需 GPU/内存
```

两个模式接口完全一致，切换只需改 `.env` 中 `AI_PROVIDER`。

### 4. 文档处理管道

```
扫描目录 → 过滤格式(md/pdf/txt)
    → PDF: pdfplumber → pypdf 回退
    → MD/TXT: 直接读取
→ 按 Markdown 标题 + 自然段落分块
→ 带重叠的分块（overlap=200）
→ 写入 SQLite + Chroma
```

### 5. RAG 流程

```
用户问题
    ↓
Chroma 语义检索（top_k=5, threshold=0.5）
    ↓
构建增强上下文（来源标注）
    ↓
AI 生成（DeepSeek/Ollama）
    ↓
返回：回答 + 来源 + 耗时 + 参考块数
```

## 与 Wukong 的对比

| 维度 | Wukong | szpeter2026 |
|------|--------|-------------|
| 定位 | 跨境数据共识匹配平台 | 个人知识库管理平台 |
| 规模 | 103 数据源、7799 字段 | 任意文档集合 |
| 数据库 | 9 种数据库统一管理 | SQLite + Chroma |
| Schema | Layer 0/1/2 三层标准 | 无固定 schema |
| AI | DeepSeek SQL 助手 | RAG 通用问答 |
| 部署 | Fossil + 多微服务 | 单文件 Flask |
| 区块链 | FISCO-BCOS 存证 | 无 |

## 扩展建议

1. **多用户支持**：添加用户认证和独立知识库空间
2. **更多文档格式**：支持 DOCX、PPTX、HTML
3. **高级检索**：混合检索（关键词 + 语义）、重排序
4. **知识图谱**：抽取实体关系，构建知识网络
5. **自动更新**：监控文档目录变化，增量索引
6. **API 网关**：为外部系统提供标准 API
7. **插件系统**：支持自定义处理器和检索器
